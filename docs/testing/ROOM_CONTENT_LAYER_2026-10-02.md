# 生成方式維持・共通部屋レイヤー・Auto・端点設定

## 原因

PR #61時点では、生成方式でBSP等を選んでも、自然文が難易度または特殊部屋に言及すると確認後に `version-3-special-rooms` へ無条件で変更されていた。例の「初心者向けダンジョン」もeasyとしてこの分岐に入る。文言だけでなく、BSP地形がV2由来のV3地形へ切り替わっていた。

## 修正方針

- 11種類すべてで、選択したStrategyが地形・接続を作り、独立した `special-rooms-1` 内容レイヤーで難易度・特殊部屋・店を適用する
- 選択Strategy ID / algorithmVersion / generatorVersionは維持。`contentLayerVersion`を別に記録し、Layout JSONの任意source項目として往復可能にする
- V3は従来の内容処理を重複適用しない。無装飾のライブラリV1/V2および既存固定ハッシュは変更しない
- 内容レイヤーは新規生成結果のコピーにだけ適用。既存の作者状態や生成元の結果を変更しない
- 複数階では前階の攻略証拠が返したHP/XP/G/装備を次階検査に渡す。Mysteryでは保存した方針を新Seedで再解決する

## UI

- Autoは確認をスキップ。自然文の明示指定を優先し、未指定値を手動確認と同じ関数で決める。初期状態はOFF、ページ内の選択として保持する
- Autoで解釈警告がある場合は黙って無視せず、入力の確認を求めて停止する
- 手動確認のCancel/Generateは右上の固定ヘッダーに配置。内容だけスクロールする
- 確認文言は実際の選択方式を表示。5言語すべてを既存のメッセージID方式へ統合
- Start / Goalは通常・ランダム・モンスターハウス・トラップハウス・店から選べる。既定はランダム
- 端点ランダムは各階・各役割ごとのSeed streamで、許可された各種類を独立に1/3で候補化し、候補から1種類を決定的に選ぶ。候補なしは通常。最終的な各種類の確率が1/3になるという意味ではない
- 追加敵・罠の容量不足ではランダム候補だけを外し、明示した端点・個数を維持する。明示指定だけで上限を超える場合は生成を拒否する
- 全体の「置かない」は端点ランダムからも除外する。端点で種類を明示した場合はその場所で優先する
- 自然文では `targetRole: start / goal` で実際の地形生成後のRoom IDへ結び付ける。通常端点はkind=normal、端点ランダムはkind=normal/presence=random。階未指定の端点設定は各階に適用
- 端点の敵数・商品は編集可能。端点の役割や指定された数・被害を攻略補正で別の部屋へ移動／減量しない

## Play / Simulation

- Startハウスは開始時の入室イベントで即起動し、全処理まで退出不可
- 特殊Goalは到着だけで終了せず、「この階をクリア」操作を表示。ハウスは未処理敵・罠がある間は拒否する
- Goal店は購入前後どちらでも終了可。0Gでも終了可。通常の店・Start店の退出も購入を条件にしない
- Goal操作は多階層では次階へ、最終階ではResultへ進む
- 既存の通常Goalは到着で終了する動作を維持
- Simulationの組み込み方策も特殊ハウス処理とGoal終了操作を扱う

## 安全な失敗

生成候補がHP収支上の有限攻略検査に通らなければ、作者状態に適用せず `FIRST_SHOP_SURVIVAL_CONFLICT` / `ROUTE_VIABILITY_CONFLICT` を返す。特殊部屋がStart/Goalにも増えるため、ランダム・高難度にも不成立候補はある。有限検査の失敗は数学的な解なしの証明ではない。勝手な生成方式変更、明示個数の削減、HPのリセットはしない。

## 実行した検証

- 新規Core回帰: 全Strategyの地形・接続・由来維持、同Seed再現、不成立時の無変更拒否、端点の固定、複数階carry
- 自然文端点の種類・数・対象階、既定ランダム、明示通常、全体除外と端点明示優先
- Startハウス／Goal敵・罠／店の購入なし・購入後終了／通常店の退出
- Layout内容レイヤー由来のexport/import、Simulation特殊Goal
- native Chromium: BSP文言、Cancel不変、5言語、キーボード、1440×900と820×540の固定ヘッダー、Autoと手動既定の一致、全11方式の選択・由来保持
- Goal店の実画面で0G購入なし・購入後終了、2階run遷移を追加検証

最新の実行結果は `artifacts/room-content-ui/smoke.json` に保存する。ライブprovider応答の網羅性と公開デプロイはこのローカル検証には含まない。既存特殊部屋smokeは端点を通常に明示して既存シナリオを固定し、新しい端点挙動は上記専用検証で扱う。
