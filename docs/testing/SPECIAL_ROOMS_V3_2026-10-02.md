# 特殊部屋・店・難易度 V3 検証

## ユーザー承認済み仕様

- 動的な敵移動や戦闘ターン制を追加しない。従来の出口／Room Events操作を維持する
- モンスターハウス／トラップハウスは全敵・罠を処理するまで退出不可
- 通常設定は敵3体、罠4個。部屋数未指定は選ばれた種類ごとラン全体で1室。種類自体の指定なしは各1/3で存在、明示include/excludeを優先
- 店はその場でHP回復、武器・防具は即装着。持ち物UIの追加なし
- 回復8HP＝10G、武器／防具T1/2/3＝10/20/30G、各在庫1。再入室で補充せず新Playでリセット
- 満HP時の回復／現在と同等以下の装備購入は拒否。G不足・売り切れも無変更で拒否
- 武器は敵からの損耗をTier分、防具は敵・罠からの損耗をTier分軽減。正の損耗は最低1HP。旧Specにルールがなければ従来通り
- やさしい：敵2／罠3、敵3HP／罠4HP、回復10HP。標準：3／4、4／6、8。難しい：4／5、5／7、8。価格は共通
- 自然文の明示指定を優先。未指定値を確認画面で提案し、承認まで作者Specを変更しない
- 手動修正した値は難易度を変更しても保持する
- 追加敵・罠は1階合計100体が標準上限。高度設定の上限は本環境の実測から250体。超過時に無言で丸めない

## 生成・経済

V1/V2実装とSeed出力を変更せず、V3 strategyを追加した。ユーザー承認でbrowser RecommendedをV3へ変更。Library defaultのV1と旧V1/V2明示選択は維持する。V3利用と各種類のrandom/include/exclude、当該Seedでの存在結果を確認画面に明示する。

指定先は明示Room IDか、Start/Goalを除くSeed選択。特殊部屋同士は重複しない。選んだ部屋の通常生成内容を指定内容へ置換する。編集済みマップへの破壊的後付け操作には使わない。多階層の指定は対象階へ一度だけ適用する。

店ごとに最も高い商品1つ分のG専用宝箱を、Startから店への決定的な最短経路上で最も手前の通常部屋に配置する。ここで「手前」は店に最も近い店より前の通常部屋を意味する。該当部屋がなければStartへ置く。Goalを経由するとフロアが終了するため、その経路は候補にしない。Gは宝箱を開けて初めて入手し、所持Gを直接増やさない。補充宝箱から装備は出さない。既存の敵／宝箱報酬も維持する。

これは回収可能な資金配置であり、宝箱を無視した場合・別の店で消費した後の残高保証ではない。確認画面にこの条件を表示する。

## 入力境界

DesignIntent v1の数値軸contractを維持し、独立したroomRequestsのJSON schemaとvalidatorを追加した。providerの未指定数値はnull。Cloud→有限retry→fallbackの既存経路を維持。生成API送信データはpromptと固定schema選択フラグのみで、作者状態／プレイヤー状態を送信しない。

Fallbackは日本語／英語の限定語彙。種類・部屋数・敵罠数・階・明示Room ID・対応商品価格／在庫を読み取り、負数／小数の個数を正数へ誤変換しない。相対配置など表現できない指定は確認が必要。ライブprovider応答の網羅性はローカルstub検証の範囲外。

## 負荷測定

環境：クラウドLinuxネイティブChromium、1440×900、ANGLE Vulkan SwiftShader。実GPUやユーザーPCの性能保証ではない。1室へactive enemyを集中したworst-case fixtureをImportして、編集シーン構築・Start・入室・1体処理を計測。フレーム値は入室直後3秒のrequestAnimationFrame間隔であり、制御されたGPUベンチマークのFPSではない。

初回：

| 敵数 | Import ms | 入室 ms | 1体処理 ms | フレーム中央値 ms | p95 ms |
|---:|---:|---:|---:|---:|---:|
| 100 | 765 | 370 | 309 | 19 | 28 |
| 250 | 778 | 554 | 480 | 64 | 104 |
| 500 | 998 | 803 | 714 | 127 | 1,407 |
| 1,000 | 1,735 | 1,685 | 1,611 | 3,004 | 3,004 |

500以上は長い停止／描画停滞が顕著なため、高度設定は保守的に250まで。250でも通常100より重いため、確認画面で注意を表示する。1000を「対応最大値」とは扱わない。上限を上げるには環境と条件を記録して再測定する。


再測定（100／250体を各2回）：250体の入室492〜514ms、1体処理435〜459ms、フレーム中央値64〜68ms。100体は同条件で概ね370msの入室を維持した。全候補でクラッシュやpageerrorはなかったが、500／1000の描画停滞は対応上限を引き上げる根拠にしない。

最終ローカル検証記録：全Node 477件0失敗（2026-10-02 05:05 UTC時点）、新機能native smoke17項目0error、syntax273ファイル、hosting build、legal/privacy監査通過。旧Room Events smokeのResultラベル期待値が直前のUI変更に追随していなかったため、DMG/HEAL/XP/LOOT/WPN/ARMから現在のDamage/Healing/EXP/Loot/Weapon/Armorへ更新した。機能側の値と意味は変更していない。


## 最終の自動配置・複数階保護

種類の有無はrandom/include/excludeの3状態。未指定は各1/3でラン全体に1室、明示あり/なしは優先。部屋・追加Entity容量が不足するときはrandom候補だけを外し、その理由を確認画面へ表示する。同じSeedと設定で再現し、Mysteryは新Seedで再抽選する。

自動配置は有限の決定的な方策で実Playを再生し、クリア経路を保存する。必要な場合だけ既存の装備箱・回復・通常敵、自動モンスターハウスの場所を調整する。数量・ID・被害・価格・報酬を変更せず、店がない設定に店を追加しない。明示条件を守って攻略例を確認できない場合、作者状態へ適用する前にエラーを返す。有限探索の不成功を数学的な『解なし』とは断定しない。

次の階の生成検査には前階の攻略例が返したHP/Level/XP/G/装備を渡し、実Runの遷移でも完全一致を検証した。各階を20HPへ戻していない。64Seed×3難易度×2/3/10階×random/include/excludeの1728走すべてで実Runクリアを確認。種類の5184組合せ検査も通過。全ての行動選択が安全という保証ではなく、確認できた攻略経路が存在することを示す。

最終ソースの集計：499 Node tests通過、hosting build・構文・legal/privacy監査通過。詳細な性能比較は PERFORMANCE_PROFILE_2026-10-02.md を参照。ライブOpenAI応答、公開デプロイは今回未検証／未実施。

最終native再実行：新機能21項目（random再現、Mystery再抽選、明示除外、実3階carry含む）、既存Room Events、生成画面、多階層、Resultの全チェック通過。ブラウザconsole/page/request/HTTPエラーなし。Result等の旧シナリオはV2を明示選択して旧動作を維持し、V3の確認画面は専用smokeで検証した。
