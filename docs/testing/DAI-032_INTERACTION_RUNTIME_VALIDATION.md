# DAI-032 Treasure / Trap / Recovery Runtime Validation

## Status

**DONE — production validation passed on 2026-09-13.**

DAI-032 adds renderer-independent runtime semantics for the remaining non-enemy PCE Play interactions: treasure, trap, and recovery entities.

Authoring entities remain inside the fixed execution snapshot. Runtime state is stored only in `PlaySession.gameplayState.entityStates`; no arbitrary generated runtime code is executed.

## Runtime contract

### Treasure

- default state: `closed`
- current-room inspect does not open the treasure
- authoring warning metadata remains readable
- current-room open is one-shot
- first successful open increments `treasuresOpened`
- successful inspect/open increments generic `interactions`

### Trap

- default state: `armed`
- current-room inspect exposes warning metadata without resolving the trap
- resolution is one-shot as either `avoided` or `triggered`
- only `triggered` increments `trapsTriggered`
- second resolution is rejected

No damage amount is assigned in DAI-032 because player HP/failure remains later scope.

### Recovery

- default state: `available`
- current-room use is one-shot
- first successful use increments `recoveryUsed`
- repeat use is rejected

No healing amount is assigned in DAI-032 because player HP remains later scope.

## Production API

`packages/play-core/src/interaction-runtime.js` exposes:

- `getTreasureState(session, treasureId)`
- `getTrapState(session, trapId)`
- `getRecoveryState(session, recoveryId)`
- `listRoomInteractables(session, roomId, options)`
- `inspectTreasure(session, treasureId, options)`
- `openTreasure(session, treasureId, options)`
- `inspectTrap(session, trapId, options)`
- `avoidTrap(session, trapId, options)`
- `triggerTrap(session, trapId, options)`
- `useRecovery(session, recoveryId, options)`

Mutating operations require a `playing` session, the correct entity type, and the entity to be in the current room. Prior PlaySession values, authoring `DungeonSpec`, and the execution snapshot remain unchanged.

## PCE-1.0 boundary

This completes the renderer-independent runtime layer needed by the frozen Perspective tasks for normal treasure, dangerous-treasure inspection, recovery use, and trap avoidance.

It does **not** constitute Perspective evidence by itself. Entity rendering/warning presentation, all three Play-camera candidates, route-judgment UI, mobile target IDs, and P01–P12 participant sessions remain required by PCE-1.0.

## Explicit non-goals

DAI-032 does not implement:

- player HP/death/failure;
- trap damage amount;
- recovery healing amount;
- treasure reward payloads;
- treasure-triggered enemy spawn;
- final entity rendering or warning visuals;
- Perspective/Combat selection;
- supported trigger/condition/action event execution;
- balance/simulation scoring.

Those remain DAI-017, DAI-033, DAI-034, renderer/UI follow-up work, and later simulation tasks.
