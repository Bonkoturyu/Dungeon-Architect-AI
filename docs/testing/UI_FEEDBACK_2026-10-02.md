# 生成設定・武具表示・店操作・通常部屋の数量差別化

## 承認された変更

- 生成設定を「自動／手動」の二択にする。自動は文章に合わせて設定し、手動は確認・調整後に生成する。選択だけでは生成せず、既存の生成ボタンを押す。初期選択は従来どおり手動
- プレイ中のステータス欄に現在の武器・防具Tierを表示。未装備は明示する。表示値は実際のPlayerStateに従い、宝箱／購入／階移動／再Playで更新
- 店のヘッダーに「店から出る」を置いて商品一覧を閉じ、通常の移動操作を使えるようにする。その場で「店を開く」も選べる。実際に別の部屋へ移動して戻ると一覧を再表示する。在庫・G・装備は閉じる操作で変更しない
- Goal店の商品一覧を閉じても「この階をクリア」は残す。購入は終了／退出の条件にしない
- Start/Goalの役割と、モンスターハウス／トラップハウス／店の種類を一覧・選択表示・詳細・プレイ見出しに併記する

提出された3体罠の画像は、Entity ID上ではStart/Goalのトラップハウスだった。種類の表示が役割名で隠れていたため通常部屋と区別できなかった。この表示修正に加え、下記の自動配置制約を適用する。

## 内容レイヤー special-rooms-2

各階・各種類について、モンスターハウス以外の部屋の敵数と、トラップハウス以外の部屋の罠数を、対応するハウスの数未満にする。

- 対応するハウスがある場合：その階で設定した最小のハウス内個数を基準にする
- 対応するハウスがない場合：既存の難易度別ハウス初期値を基準にする
- 例：やさしいの未配置ハウス基準は敵2／罠3なので、非ハウス部屋は敵1以下／罠2以下
- 最初に自動内容を通常部屋へ分散し、分散先の余地がなければ自動生成分の超過だけを除く
- Start/Goalへ危険を押し付けたり、店への既知の安全経路へ敵を追加したりしない
- 明示ハウスの個数・配置・被害・店の商品、参照される内容を勝手に変更しない。明示条件を守れない場合はエラーで作者状態を保持する
- 数量制約を守る範囲で攻略経路を再検査する。生成方式の地形・接続は変更しない
- 実際のEntity総数と、移動／削除した自動Entityはdiagnosticsに記録する

出力に影響するため、内容レイヤーの既定版を `special-rooms-2` に進めた。`applyRoomContentLayer(..., { version: 'special-rooms-1' })` または `applyRoomContentLayerV1` で従来経路を保存する。基礎Generator VersionとAlgorithm Versionは変更しない。

## 端点指定の残存不具合

- floorNumberごとに端点種類を保持する。同じ階・同じ役割への相反する種類だけを衝突として拒否し、全階既定に対する階別の具体指定を優先する
- 手動確認に自然文で指定された階別の選択肢を表示し、難易度変更や再解決で値を潰さない
- 別のStart/Goal句を導くand／but／日本語の区切りだけを節境界として扱う。種類同士のand、個数、否定を維持する
- 整数の階数で終わる英文の終止ピリオドを節境界にする。小数・負の階数は引き続き拒否する
- 実際のHTTP handler → router → fallback parserを使う回帰テストを追加。無関係な自由文の全面対応を主張しない
