# 右上リザルトパネルの情報設計とゲーム UI 参考資料

調査日: 2026-10-02
対象: Dungeon Architect AI の Result 表示
位置づけ: 今回の局所的な UI 改善の設計根拠。アクセシビリティ適合認証や実装検証の完了報告ではない。

## 結論

所有者の最新指定は「今、プレイ中のがめん下のプレイヤーのステータスと同じように分かりやすいのにしてね」。既存の Play 下部ステータスを主な視覚基準とし、外部のゲーム UI 資料は補助根拠とする。

クリア・終了の見出しを最上段に置き、その下の13項目を「プレイヤー」「装備」「攻略結果」の3群に分ける。プレイヤー群では既存下部 HUD と同じ `LV → HP → EXP → G` の順・ラベル・数値の見せ方を使う。他の項目は意味の分かる名前で整列する。項目を減らしたり、小さい文字で圧縮したりせず、右上の限られた幅の中で読む順序を作る。

所有者提供の切り抜き画像では、クリア見出しの下に `FLOOR / HP / LV / XP / G / LOOT / WPN / ARM / DMG / HEAL / 敵 / 宝箱 / 罠` が中央寄せで連続して折り返されている。問題は数値の多さだけでなく、分類・列・読む順序が見えないことにある。切り抜きだけから画面全体の占有率や実際の CSS 文字サイズは断定しない。

本書の項目順・寸法は、このプロジェクトへの適用案であり、以下の外部資料が同じ配置を指定しているわけではない。

## 一次資料と採用する考え方

### Xbox Accessibility Guideline 101 Text display

資料: [Microsoft のゲーム向け文字表示ガイド](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)

確認した内容:

- 文字の大きさだけでなく、書体・余白・整列・拡大時の表示を扱う。
- PC/VR の1080p表示では、標準文字の最低値として18pxを示す。ただしこれは描画された文字の body height を測定する値であり、CSS の `font-size: 18px` と同義ではない。
- 200%への文字拡大で内容・機能・意味を失わず、見出しの階層を保ち、縦横の二方向スクロールを要求しないことを推奨する。

今回への適用: 数値とラベルの整列、見出しとの大小差、縦スクロールによる内容保持を優先する。CSS の設定値だけで XAG 適合を宣言しない。

### Xbox Accessibility Guideline 102 Contrast

資料: [Microsoft のゲーム向けコントラストガイド](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)

確認した内容: 通常サイズの重要な文字・要素には背景との4.5:1以上のコントラストを示す。背景が一様でなければ最もコントラストが低い箇所を評価する。色だけに情報を依存させない。

今回への適用: パネルには暗い安定した背景を使い、補助ラベルも薄くしすぎない。クリア／終了は緑／赤の色分けに加えて文字で明示する。半透明背景を使う場合は明るいゲームシーン上でも確認する。

### Game Accessibility Guidelines Use simple clear text formatting

資料: [ゲーム向けの読みやすい文字組み](https://gameaccessibilityguidelines.com/use-simple-clear-text-formatting/)

確認した内容: 短い文章でも、判別しやすい書体と煩雑でない背景が有効。長文向けには左寄せ、過度な全大文字の回避、行間などを挙げている。

今回への適用: 言語に合った読みやすいフォントを使い、`WPN`、`ARM`、`DMG` の解読を要求しない。一方、既存下部 HUD にある `LV / HP / EXP / G` は所有者の指定した一貫性を優先して再利用する。数値群を長文のように中央寄せで折り返さない。長文向けの行長規定を小さな数値セルに機械的に当てはめない。

### Factorio Statistics GUI

資料: [Wube Software 開発記事 Friday Facts 337](https://www.factorio.com/blog/post/fff-337)

確認した内容: 開発元が実際のゲーム内統計画面を掲載している。関連する電力指標を横並びにし、数値表示を太いバーの内部へ移動した例や、複数領域で検索操作を共通化した理由を説明している。

今回への適用: 関連する数値を近接させ、ラベルと値の所属を見失わない構造にする。今回は13項目の静的な結果なので、グラフ・検索・複雑なタブまでは追加しない。ゲーム内統計画面の参考であり、勝利画面そのものの事例ではない。

### Halo Waypoint Post Game Carnage Reports

資料: [Halo 公式の試合結果レポート紹介](https://www.halowaypoint.com/news/halo-waypoint-game-history-post-game-carnage-reports)

確認した内容: 公式記事は Player Recap の画面画像を公開し、試合履歴からスコアボード、キル、目標への貢献、命中精度、メダル、ランク変動などの詳細を確認できる構造を説明している。これはゲームの試合結果を扱う Web／モバイルのコンパニオン UI であり、ゲーム内 HUD と同一ではない。

今回への適用: 「結果はどうだったか」と「何が残り、何が起きたか」を分けて読ませる。全面的な結果ポータルや画面遷移を模倣せず、右上カード内の見出しと情報群に要点だけを移す。

外部の画面画像・フォント・アイコンは実装資産として取り込まない。上記は閲覧可能な原典へのリンクと設計上の要約であり、プロジェクトの CC0 創作資産方針を変更しない。

## 表示項目と意味の保存

意味は調査時点の `apps/editor-slice/main.js` の `renderResultMetrics` と、`packages/play-core/src/play-session.js`、`progression-runtime.js` を照合した。

| 群 | 旧表示 | 表示名 | 保持する値と注意 |
| --- | --- | --- | --- |
| 攻略結果 | FLOOR | 踏破階 | 完了階数 / 総階数。現在階と混同しない |
| プレイヤー | HP | HP | 最終HP / 最大HP |
| プレイヤー | LV | LV | 最終レベル |
| プレイヤー | XP | EXP | 現レベル内の経験値 / 次レベル必要量。今回の獲得経験値ではない |
| プレイヤー | G | G | 最終所持金。`goldEarned` へ置き換えない |
| 攻略結果 | LOOT | 戦利品 | `lootCollected`。取得アイテム数であり、開封宝箱数ではない |
| 装備 | WPN | 武器 | 最終装備の Tier。未装備は「—」を保持 |
| 装備 | ARM | 防具 | 最終装備の Tier。未装備は「—」を保持 |
| 攻略結果 | DMG | 被ダメージ | `damageTaken`。与ダメージではない |
| 攻略結果 | HEAL | 回復量 | `healingReceived`。回復行動回数ではない |
| 攻略結果 | 敵 | 敵 | `enemiesCleared`。敵撃破数 |
| 攻略結果 | 宝箱 | 宝箱 | `treasuresOpened`。宝箱開封数 |
| 攻略結果 | 罠 | 罠 | `trapsTriggered`。罠作動数であり、回避・発見数ではない |

`G` は既存下部 HUD と同じ所持金であり、獲得金額へ算出式を変更しない。複数階の結果でも数値の取得元は変更しない。現行実装は `dungeonRunSession.floorResults.at(-1)?.result` を `lastPlayResult` として表示するため、戦利品・被ダメージ・回復量・敵・宝箱・罠のカウンターは最後に終了した階の結果であり、ラン全体の合計ではない。踏破階は `lastDungeonRunResult` の完了階数／総階数を使い、プレイヤー状態は階をまたいで引き継がれた終了時の値を表示する。ラン全体への集計変更は今回の表示改善に含めない。

## 配置と文字の設計

- 上から「結果見出し → プレイヤー → 装備 → 攻略結果」。プレイヤーは `LV → HP → EXP → G`、装備は武器・防具、攻略結果は踏破階・戦利品・被ダメージ・回復量・敵・宝箱・罠の順にする。
- 下部 HUD の暗い背景、太い等幅の数値、既存のラベル表現を再利用する。下部 HUD と異なる装飾書体や、新しい説明のないアイコンは足さない。アイコンを使う場合も既存の意味・表現と一致させ、数値とラベルを省かない。
- 各群は薄い区切り線と短い見出しで分ける。13個すべてを個別の強い枠で囲わず、情報のまとまりを見せる。
- 標準幅では1行に2項目。各項目内はラベルを左、数値を右に揃える。ラベルと数値が別の項目へ流れ込まない DOM と列構造にする。
- 右上カードの幅は約340 CSS pxを初期目安とする。画面幅からはみ出さず、中央のキャラクター・部屋・イベント表示を大きく覆わないことを実画面で確認して調整する。
- 値は下部 HUD に合わせた太字・等幅の16 CSS px以上を初期基準とする。ラベルは既存の metric-label 表現を基準にし、実画面で小さすぎないか確認する。結果見出しは数値より一段大きくする。これは既存画面との一貫性を保つ局所改善の基準であり、XAG最低値を満たす保証ではない。
- カード内余白12–16px、群間12–16px、項目間8–12px程度を出発点とする。行高は文字を切らない余裕を確保する。
- 大きい値や翻訳文字列は折り返し、必要に応じて項目を1列へ変更する。値を省略記号で失わせたり、収めるために文字を縮めたりしない。
- 画面高が低い場合・拡大時はカードの高さを画面内に制限し、内部を縦スクロール可能にする。スクロール領域がキーボードでも到達・操作できることを確認する。
- Result だけに適用する。Play 下部HUDの `LV → HP → EXP → G` 順序、中央のルームイベント、エラー通知の優先順位は既存仕様を保つ。

## 受け入れ確認

下記は確認すべき条件であり、本書作成時点の合格実績ではない。

1. クリアと敗北・終了の両方で見出しと13項目が存在する。値の0も消えず、未装備は区別できる。プレイヤー群のラベル・順序が下部 HUD の `LV → HP → EXP → G` と一致する。
2. 英語・日本語・簡体字・繁体字・韓国語で、翻訳漏れや文字切れがなく、数値が隣の項目に見えない。
3. 1440×900の主対象と1280×720程度の低いデスクトップで、カードが画面内に収まり、中央のゲーム画面を必要以上に隠さない。
4. ブラウザ200%拡大で全項目を縦方向に読める。横スクロールや画面外への脱落を起こさない。これは独立した文字拡大機能の完全検証とは区別する。
5. 4桁以上の値、長いラベル、HP・経験値の分数を入れて、はみ出し・重なりを確認する。
6. Play 下部 HUD と Result の両スクリーンショットを比較し、同じステータスとして読み取れることを確認する。ラベル・数値・見出しの実際の描画と背景コントラストを確認する。透過背景は明るい場面でも評価する。
7. HTMLの意味構造と読み上げ順が「群見出し → ラベル → 値」に沿い、スクロール領域をキーボードで操作できる。
8. 既存 Play HUD、ルームイベント、再開始、Edit 復帰、複数階結果の回帰テストを実行し、実施した検証だけを報告する。

狭幅・モバイルは既存の desktop-only / best-effort 方針を維持する。今回の修正だけで正式対応へ変更しない。
