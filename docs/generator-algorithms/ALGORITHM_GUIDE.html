Dungeon Architect AI

Dungeon Generation Algorithm Guide

「何をしているアルゴリズムか」「どんなDungeonになりやすいか」「このプロジェクトでどう使うか」を、 簡単な図解と実装視点の両方で整理した資料。

Overview Core Architecture Markdown

Version 1 — Classic

一言: StartからGoalまでの主経路を先に保証し、少数のshortcutを足す方式。

Topology

Start ─ 02 ─ 03 ─ 04 ─ 05 ─ Goal
          ╲________╱
          alternate route

Spatial layout

01 02 03 04
08 07 06 05
09 10 11 12

Sequential backboneを作り、routeChoiceに応じて2～4 Room先へのalternate edgeを追加。その後、固定4-column serpentine gridへ配置する。

強み

再現性、到達性、デバッグ性、回帰比較。

弱み

同じroomCountでは空間配置が似る。branch/dead-endの表現が弱い。

役割

Frozen baseline。比較・再現用に残す。

Seed A

      02
      │
04 ─ 03
│

Seed B

05 ─ 04 ─ 03
          │
          02
          │
          01

Seedによりcolumns、spacing、rotation/mirror、first-row direction、Room width/depthを変える。Gameplay topology、Entity count、Entity placement ruleはV1系を維持。

強み

V1の安全性を保ちながら視覚variationを増やせる。

弱み

TopologyそのものはV1系。Algorithm固有の探索構造までは変えない。

役割

Current Recommended。将来Recommended aliasは別Versionへ付け替え可能。

BSP — Binary Space Partitioning

一言: 大きな土地を何度も二分し、その区画にRoomを置く。
+-----------------------+
|           |           |
|   [A]     |    [C]    |
|-----------+-----+-----|
|    [D]    | [E] | [F] |
+-----------+-----+-----+

全体boundsを縦/横に再帰分割し、leafにRoomを置き、sibling subtree間をCorridorで接続する。

できやすい形

整然とした区画、施設・地下建築物らしいRoom配置。

強み

overlap回避、空間利用、deterministic化が容易。

弱み

四角い区画感が出やすく、gameplay意味付けは別途必要。

DesignIntent対応例: exploration↑ → leaf/optional link↑、routeChoice↑ → extra connection↑。

Scatter + Delaunay + MST + Loops

一言: Roomを自然に散らし、近いRoom同士の候補から最低限の接続と必要なloopを作る。

Scatter / candidate

      A
     / \
    B---C
     \ / \
      D---E
     /
    F

MST + loop

      A
     /|
    B-C
      |
      D---E
      |
      F

Room centerをscatterし、overlapをseparationした後、Delaunay edgeからMSTを作り全体接続を保証。未採用edgeの一部をloop/shortcutとして戻す。

できやすい形

organic、irregular、shortcutとloopのある探索型。

強み

Seed差が大きい。MSTで接続性を確保しやすい。routeChoiceと相性が良い。

位置づけ

Algorithm Labで最初に実装する有力候補。

Rooms + Mazes

一言: Roomを置いた残りの空間をMazeで埋め、最後に全部つなぐ。
+----------------------+
| [Room]  ─┐ ┌─┐      |
|          │ │ └──┐   |
| ┌───┐    │ └─┐  │   |
| │   └────┘   │[Room]|
| └────────────┘      |
+----------------------+

non-overlapping Room配置 → maze carving → region connector → extra connector → dead-end pruningという流れ。

できやすい形

Roomと複雑なCorridorの混合。classic roguelike感。

強み

探索密度が高く、loop量やdead-end量を調整可能。

注意

tile-gridからDungeonSpecへRegion/Connector Adapterが必要。

Random Walk / Drunkard's Walk

一言: ランダムに歩いた跡を床にしていく。
Start
  ↓
  ↓ → → ↓
        ← ↓
        ← ← →

wall grid上をwalkerがSeed PRNGで移動し、通過セルをfloorへ変える。

できやすい形

organic、irregular、cave-like。

強み

簡単、variation大、連結領域を作りやすい。

弱み

高水準のbranch数、Start/Goal距離、reward structure制御が弱い。

Cellular Automata

一言: ノイズを近傍ルールで何度もならし、自然な洞窟を作る。

Initial noise

##.#..#
.#..###
###....
..##.#.

Smoothed

####...
###....
##.....
...###.

initial wall ratio、近傍wall threshold、iteration数で形状を調整。最後にconnected component解析とrepairが必要。

強み

洞窟らしいvisual identity。密度・滑らかさを調整しやすい。

弱み

disconnected caveが出る。global gameplay controlが弱い。

統合

Cell IR → Region Graph → DungeonSpec Adapter。

Maze Carving

一言: grid全体を通路として接続する迷路生成系。
+---+---+---+
| S |       |
+   +---+   +
|       |   |
+---+   +   +
|       | G |
+---+---+---+

Recursive Backtracking、Prim、Kruskal、Ellerなどで生成の癖が変わる。

Subtype傾向
Recursive Backtracking長いcorridor、depth-first的
Primbranchが増えやすい
Kruskalregion統合、spanning treeとして理解しやすい

Gameplay Graph / Graph Grammar

一言: 地形より先に「どんな体験をどんな順番でさせるか」を作る。
Start
  │
  ▼
Combat
  │
  ├──────► Risky Reward
  │          │
  │◄─────────┘
  ▼
Puzzle / Gate
  │
  ▼
Boss
  │
  ▼
Goal

DesignIntentを高水準ruleへ変換し、semantic nodeとedgeを生成してからRoom Graph / spatial layoutへ埋め込む。

強み

Prompt / DesignIntentとの親和性が非常に高い。意味のあるbranchやpacingを設計可能。

弱み

rule設計とgraph→geometry embeddingが複雑。

位置づけ

将来のRecommended候補として最重要。

Wave Function Collapse — WFC

一言: 隣り合ってよい部品のルールを守りながら候補を少しずつ確定する。

Before

[ABC][ABC][ABC]
[ABC][ A ][ABC]
[ABC][ABC][ABC]

Propagated

[AB ][ B ][BC ]
[AB ][ A ][BC ]
[AB ][ B ][BC ]

entropyの低いcellをcollapseし、adjacency ruleを周囲へpropagate。contradiction時はretry/backtrack。

強み

local ruleの一貫性、sample/style反映、module組み立て。

弱み

global Start→Goalやgameplay progressionは単独では扱いづらい。

統合

Global Graphの後段でRoom内部や3D module生成に使うのが自然。

Hybrid + Simulation Selection

一言: 複数候補を生成してSimulatorで評価し、DesignIntentに最も近い候補を選ぶ。
             ┌─ Candidate A ─ Sim ─ 0.71
DesignIntent ├─ Candidate B ─ Sim ─ 0.88  ← select
             ├─ Candidate C ─ Sim ─ 0.62
             └─ Candidate D ─ Sim ─ 0.79

Start→Goal距離、branch、dead-end、cycle、damage、reward、clear rate、target durationなどでscoreを構成する。

強み

品質を生成ruleだけに頼らず、既存Simulatorを活用できる。

弱み

生成コスト増、score設計、deterministic candidate selectionが必要。
