Algorithm Lab — Rooms + Mazes

Status: DAI-100 implementation candidate.

Strategy ID: algorithm-lab.rooms-mazes

Architecture

Reusable Rooms + Mazes Core
→ plain-data maze/Room graph
→ Dungeon Architect AI adapter
→ validated DungeonSpec
→ existing renderer / Editor / Play

Algorithm

  1. Select a connected seeded subset of coarse grid cells.
  2. Build cardinal adjacency for those cells.
  3. Carve a perfect maze with seeded depth-first traversal.
  4. Find the tree diameter and map its endpoints to first/last Room IDs.
  5. Create non-overlapping Room rectangles at cell centers.
  6. Add a bounded deterministic subset of unused local adjacencies as loops.

Why this mapping

All final edges join cardinally adjacent cells. The product adapter can therefore emit exact north/east/south/west doorway hints and reuse the current orthogonal-corridor renderer without introducing algorithm-specific runtime geometry.

Inputs

  • seed
  • roomCount 3–64
  • extraConnectionRatio 0–1
  • roomSizeMin / roomSizeMax
  • cellSpacing

Output invariants

  • exactly N Rooms;
  • exactly N−1 perfect-maze tree edges;
  • connected graph;
  • no self/duplicate edges;
  • all edges are cardinal local adjacencies;
  • deterministic Seed behavior;
  • plain JSON-compatible Core output.

Product adapter

The accepted Generator V1 path supplies DesignIntent-derived content counts. Rooms + Mazes replaces only spatial Rooms/Corridors, then validates the resulting DungeonSpec. Tree edges become backbone; loop edges become alternate.
