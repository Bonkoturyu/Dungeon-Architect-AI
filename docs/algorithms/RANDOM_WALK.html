Algorithm Lab — Random Walk

Status: DAI-100 implementation candidate.

Strategy ID: algorithm-lab.random-walk

Architecture

Seeded walker
→ discovered coarse-grid cells
→ first-discovery spanning tree
→ optional local adjacency loops
→ Dungeon Architect AI adapter
→ validated DungeonSpec

Algorithm

  1. Begin at grid origin.
  2. Walk in seeded cardinal directions with bounded directional persistence.
  3. Record each unique visited cell.
  4. Create one discovery-tree edge whenever a new cell is first reached.
  5. Use seeded frontier recovery after excessive revisits.
  6. Find the discovery-tree diameter and map it to first/last Room IDs.
  7. Create Room rectangles on visited cells.
  8. Add a bounded subset of unused cardinal adjacencies as loops.

Key distinction

Unlike Rooms + Mazes, Random Walk does not choose a cell region first and then carve a maze. The walker trajectory determines both the visited spatial footprint and the discovery tree.

Inputs

  • seed
  • roomCount 3–64
  • extraConnectionRatio 0–1
  • roomSizeMin / roomSizeMax
  • cellSpacing
  • directionPersistence 0–0.95
  • escapeAfter 8–512

Invariants

  • N Rooms and N−1 discovery-tree edges;
  • connected graph;
  • no self/duplicate edges;
  • cardinal local edges only;
  • deterministic Seed behavior;
  • plain JSON-compatible Core output.

Product adapter

The accepted Generator V1 path supplies DesignIntent-derived content semantics. Random Walk replaces only Rooms/Corridors. Discovery edges become backbone; adjacency loops become alternate. Exact cardinal doorway hints are emitted for every Corridor.
